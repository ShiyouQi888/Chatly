# Chatly 客户端视觉审计与统一记录

**审计日期：** 2026-11-03  
**依据：** [Chatly 设计系统](CHATLY-DESIGN-SYSTEM.md)、React/CSS 实现、已有聊天界面审计。  
**范围：** 登录、聊天与会话、通讯录、动态、社群、个人中心、消息与资料面板、搜索、媒体、投票、位置及常用浮层。运营后台保留独立的管理端设计语言。

## 审计结论

项目已有完整的业务页面和一套可复用的 CSS 令牌，但旧配色、固定浅色表面、分散圆角与阴影、过小控件和主题设置的不完整实现，使各页面看起来像不同阶段的产品。新的设计基线已贯穿客户端基础令牌、常用页面和组件：浅色/深色主题、五套品牌色、类型比例、4pt 间距、形状、表面层级和重点触控尺寸由同一套语义变量驱动。

产品导航保留五个现有入口，包括独立的“通讯录”。设计系统原型中的四项导航视作示例信息架构，不作为删减或重排现有业务入口的要求。

## 主要发现与处理

| 优先级 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 五套主题沿用旧色板，主题文字色固定为白色，薄荷/琥珀/蜜桃动作色对比不足 | 更新为设计系统色板；每个主题声明 `onPrimary`；对消息/按钮渐变端点进行对比度校正 |
| P1 | 浅色表面、表单和正文色值直接写在多个页面，缺少深色映射 | 建立 canvas / surface / input / line / text 语义令牌及客户端深色模式覆盖 |
| P1 | 主题外观没有真实明暗模式设置，设置列表包含未接入的假入口 | 提供跟随系统、浅色、深色三种模式并持久化；移除虚假的背景/气泡/强调色行 |
| P1 | 旧主题色和跨页面品牌紫硬编码导致选主题后部分页面不变 | 将旧色替换为品牌/状态令牌，统一主题更新入口 |
| P2 | 圆角、阴影、间距值和字体字号各页自行决定 | 统一为 8/12/18px 圆角、E0/E1/E2 层级、4pt 布局间距与角色字号 |
| P2 | 若干常用图标、开关、选择按钮和输入控件的点击区域低于规范 | 将导航图标、设置返回、开关、表单动作、通讯录辅助控件和消息发送控件收敛到 44px 触控基准 |
| P2 | 白字按钮和失败状态复用品牌/危险色，文字对比取决于颜色组合 | 拆分主题前景色与危险动作色，错误文字使用可读的 `--danger-ink` |
| P2 | README 与项目令牌及附件规范不一致 | 将设计系统纳入 `docs/`，同步主题与模式说明 |

## 已落地的设计基线

### 色彩和主题

| 主题 | 色板 | 动作文字 |
| --- | --- | --- |
| 极光 | `#6d5df6 → #5b4bd8` | 白色 |
| 薄荷 | `#34d3a6 → #2bb595` | `#06382c` |
| 蜜桃 | `#f97ca8 → #cf3f75` | 白色；动作渐变端点自动加深 |
| 琥珀 | `#ffb43f → #f5a028` | `#3d2600` |
| 石墨 | `#4a4a5a → #3a3a4a` | 白色 |

`--primary` / `--brand-2` 表示能在当前表面阅读的品牌墨色；`--brand-grad` / `--brand-action` 表示按钮和我方气泡表面；`--on-primary` 决定表面上的文字色。亮色主题原始色仍用于色板展示，承担正文的色值会经过对比校正。

明暗模式作用于 Chatly 客户端，不改变独立运营后台。`chatly-mode` 保存 `system`、`light` 或 `dark`；系统模式监听设备外观变化。旧主题名会映射到最接近的新色板，避免用户已有偏好失效。

### 字体、间距和形状

- 字体：Noto Sans SC；页面标题 28px、栏目标题 20px、列表标题 16px、正文 15px、次级信息 13px、时间/徽标 11px，继续服从全局字体缩放。
- 间距：以 4pt 为基础；已有 2px 仅用于少量视觉微调。主间距包含 4、8、12、16、24、32px。
- 圆角：8 / 12 / 18px，消息尾角 6px，头像和胶囊 999px。
- 层级：E0 平面和分隔线、E1 收到的气泡、E2 面板/菜单/弹窗；普通卡片不再使用装饰性重阴影。
- 触控：高频导航、切换和主要操作控件至少 44px。

### 聊天语义

- `--chat-canvas`、`--chat-surface`、`--chat-control`、`--chat-divider` 统一聊天页、列表、输入区和底栏。
- 收到消息使用语义化浅/深内容面并采用 E1；我方消息使用主题渐变和 `--on-primary`。
- 普通文字按 `--text-1/2/3` 分级，`--text-4` 只用于装饰。
- `--danger-ink` 用于错误文字，`--danger-action` 用于承载白字的危险动作底色。

## 实施状态

### 阶段 1：聊天基础系统 — 已完成

- 首页、会话房间、状态条、输入区和底栏共享基础与 `--chat-*` 令牌。
- 修正可读信息、状态小字、消息尾角、气泡宽度和输入区触控尺寸。
- 清理聊天页过时品牌色和不再使用的样式。

### 阶段 2：聊天次级界面 — 已完成

- 搜索、表情、转发、位置、媒体、投票、消息菜单及群设置使用共享色阶和形状。
- 错误、危险、警告、在线、未读和焦点状态分别使用语义色。

### 阶段 3：全客户端收敛 — 已完成

- 登录、通讯录、动态、社群、个人中心和资料/设置面板使用同一组浅色/深色表面、品牌色、类型比例、圆角与间距规则。
- 更新五套主题及偏好恢复逻辑，统一常用切换、表单和图标控件。
- 保留通讯录独立导航入口与现有业务路由。

### 阶段 4：交付视觉检查 — 待执行

- 在 360px、390px、桌面预览和设备安全区查看布局、滚动和字号缩放。
- 逐一查看五套配色在浅色/深色下的按钮、气泡、图标、焦点环和危险状态。
- 重拍 `shots/` 页面图，并对照实际功能核验加载、空态、失败、离线、多选、长文本和群公告。
- 检查键盘焦点、屏幕阅读器名称、减少动态效果和高缩放表现。

## 后续维护

1. 新样式优先使用 `src/styles/tokens.css` 中的基础令牌或 `--chat-*`，不复制色值、圆角和阴影常量。
2. 新主题必须声明 `onPrimary`，并检查实心动作、渐变两端、软背景与焦点环的对比度。
3. 主题和暗色覆盖仅作用于真实品牌/表面语义；媒体内容、状态色和运营后台各自保留语义边界。
4. 未接入的业务能力不进入可点击的界面；视觉状态必须由真实数据与状态驱动。
