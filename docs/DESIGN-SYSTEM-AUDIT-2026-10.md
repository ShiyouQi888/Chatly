# Chatly 设计语言系统复审

> 审查日期：2026-10-22  
> 审查基准：[`DESIGN-SYSTEM-CHATLY.md`](./DESIGN-SYSTEM-CHATLY.md)（CDLS v1.0）  
> 范围：App 运行时样式、组件、主题机制、CDLS 规范与配套令牌文件。  
> 方法：静态代码与文档核对；本报告不代表完成真机视觉、读屏器或完整 WCAG 测试。

## 结论

CDLS v1.0 是清晰的目标规范，但尚未成为 App 的运行时单一事实来源。配套令牌位于 `docs/chatly-tokens.css`，App 实际加载 `src/styles/tokens.css`；运行时代码没有引用 `--cl-*` 令牌。因此应把文档规格与已经上线的规则分开记录，不能把目标写成当前已完成。

本复审替代本文件此前版本。旧版中“间距、层级、动效令牌不存在”“全站没有焦点样式”以及旧文字对比度、旧主题色等结论已不符合当前代码。

## 已有基础

- App 运行时定义了品牌色、背景与表面、文字色、圆角、字号、动效时长、间距、z-index 和焦点环令牌：`src/styles/tokens.css`。
- 全局 `:focus-visible` 样式已在 `src/styles/global.css` 实现。
- 字号缩放、品牌主题色切换和减少动效机制已在 `src/utils/theme.js` 实现。
- 后台使用独立的暗色变量和 Tailwind v4 / shadcn 风格组件；这是独立运营界面，不应套用 App 的浅色表面。

## 发现

### P1：设计令牌与运行时分离

`docs/chatly-tokens.css` 没有被 App 导入，`src/` 也没有 `--cl-*` 引用。文档中的语义色、完整暗色表面、触控尺寸和规范化组件值尚未作用于实际页面。

**影响：** 设计稿/令牌页与用户实际看到的界面可能不一致；新页面无法仅凭 CDLS 令牌复用现有样式。

### P1：未定义的表面令牌被实际引用

`src/screens/chat-room.css` 使用 `var(--surface-3)` 绘制上传进度轨道，但运行时 `src/styles/tokens.css` 未定义该变量。该 CSS 声明会失效，轨道缺少背景底色。

**建议：** 在运行时定义兼容别名，或将引用迁到已存在的 `--cl-surface-3` 并完成其接线。

### P1：`text-4` 被用于承载信息

运行时 `--text-4` 为 `#9a9ab0`，白底对比度约 2.75:1。CDLS 和运行时令牌注释现已明确将它限制为非文本装饰，但多个页面 CSS 仍把它用于 ID、时间、说明等可读文本，和“所有可读文字至少 4.5:1”相冲突。

**建议：** 保留低对比度色只给非文本装饰；占位符、时间和必要的次级信息改用 `--text-3` 或专用 `--text-muted`。

### P1：语义色缺失，操作组件覆盖有限

运行时 `tokens.css` 没有统一的 danger/success/warning/info 语义色。错误与删除状态仍由各页面直接指定颜色。项目已有 `src/components/ui/button.jsx` 和 `src/components/ui/input.jsx`；目前主要在运营后台及其弹窗中使用，App 页面组件仍大量依赖各自的 CSS 和原生控件，尚未形成全 App 的统一覆盖。

**影响：** App 内同一交互角色容易出现颜色、尺寸、焦点和禁用状态差异；后台组件也需要按页面统计覆盖面。

### P2：令牌存在，但使用没有收敛

间距、层级和动效刻度已定义，但页面仍有直接写入的像素值。字号缩放只对引用 `--fs-*` 的样式生效，直接写 `font-size` 的页面文字不会随系统设置缩放。运行时字号刻度也和 CDLS 的 8 阶字阶不完全一致。

**建议：** 先约定新代码必须引用令牌，再按页面迁移已有字面值；把未迁移范围留在清单中，不再报告令牌“缺失”。

### P2：触控尺寸没有统一落实

CDLS 目标是最小 44×44px 触控区域；运行时没有 `--tap-min`。例如 MeTab 中编辑和二维码按钮定义为 32×32px，低于规范目标。

**建议：** 为图标按钮提供至少 44×44px 点击区域，视觉图标可保持较小；为小尺寸例外写明原因。

### P2：App 暗色模式尚未接入

`docs/chatly-tokens.css` 包含 `[data-theme="dark"]` 规则，但 App 没有加载该文件或根据主题切换 `data-theme`。当前 App 的主题切换主要更新品牌色；后台暗色模式不等于 App 暗色模式。

**建议：** 将完整暗色主题列为未接入功能，完成运行时接线和各屏复核后再标记为已实现。

## 修订后的整改顺序

1. 修复运行时缺失的 `--surface-3`；将承载信息的 `--text-4` 用法迁至可读颜色。
2. 将 `docs/chatly-tokens.css` 中的映射核对后接入运行时，明确唯一权威令牌文件；配套 CSS 尚未导入 App。
3. 增加 App 语义色，并把已有 Button/Input 原语逐步用于 App 页面，统一状态、尺寸与焦点样式。
4. 按 44px 触控目标检查主要图标按钮；统一字号与间距令牌使用。
5. 将暗色模式作为独立实现项接入 App，并用真实页面验证明暗对比。
