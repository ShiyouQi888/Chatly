# Chatly 运营管理后台 · 设计与功能审计

**更新日期：** 2026-11-03  
**范围：** `/qishiyou` 运营管理后台。普通聊天客户端与运营后台继续使用各自独立的视觉系统和登录态。

## 产品目标

后台围绕社区日常运营建立可追踪的工作流：先看运行与待办，再进入用户、内容或反馈处理；权限、敏感查阅与管理变更有明确边界并留下审计记录。界面不暴露尚未接入的按钮，也不把普通聊天账号当成后台管理员。

## 信息架构

| 分组 | 模块 | 主要操作 |
| --- | --- | --- |
| 工作台 | 运营总览 | 用户、活跃、会话、消息、动态和待办反馈概览；服务健康；快捷处理；7/30 天趋势 |
| 工作台 | 数据分析 | 新增用户、日活用户、消息、动态的 7/30 天趋势；每日明细；CSV 导出 |
| 社区管理 | 用户管理 | 按昵称、账号、ID 搜索；状态筛选；公开资料；本页导出；带原因停用与恢复 |
| 社区管理 | 内容治理 | 搜索公开动态；查看发布者、媒体和互动摘要；填写原因移除 |
| 社区管理 | 评论审核 | 搜索评论；查看回复关系和关联动态；填写原因删除 |
| 社区管理 | 反馈工单 | 按状态筛选与分页；查看文字和截图；流转待处理、处理中、已解决、已关闭 |
| 系统管理 | 私聊查阅 | 仅授权超级管理员可查；先填写原因；分页读取；无附件下载；关闭即清除正文状态 |
| 系统管理 | 操作审计 | 搜索、分页和本页导出；查看操作人、目标、原因和敏感查阅范围 |
| 系统管理 | 服务状态 | 当前实例、数据库与 Redis 快照；更新管理员账号及密码；展示权限与数据边界 |
| 系统管理 | 后台成员 | 创建独立账号；分配内容审核、客服运营或数据分析角色；调整角色或停用成员 |

## 已落地的体验改进

- 后台登录使用独立的深色工作空间布局；首次未配置管理员时展示明确的 `server/.env` 配置指引。
- 桌面侧栏可折叠，窄屏改用可关闭抽屉；模块导航可通过 `Ctrl/⌘ + K` 搜索。
- 模块使用 URL hash 保存当前页，支持刷新、复制链接和浏览器前进/后退；无权限模块自动回到可访问页面。
- 总览状态每 60 秒同步一次；手动刷新不再卸载当前页面。同步失败时保留上次数据并提供重试。
- 独立数据分析页提供 7/30 天范围、四项指标、每日明细和 CSV 导出。
- 用户、动态、评论、反馈、审计和成员页面统一显示加载错误与重试入口；反馈分页和状态筛选共享同一请求状态。
- 账号密码字段提供显隐控制；敏感管理与删改动作沿用原因确认、服务端权限校验和审计机制。
- `/qishiyou%60` 这类尾部误带反引号的本地地址会规范到 `/qishiyou`。

## 权限与安全边界

- 后台管理员与普通用户账号、会话、权限相互独立；成员导航与服务端角色权限一致。
- 客服、内容审核、数据分析成员仅看到其被授权的模块；敏感私聊正文仅超级管理员拥有读取权限。
- 私聊列表不返回正文预览；查阅原因、会话、消息范围与管理员身份写入审计；媒体只显示类型，不给下载地址。
- 停用用户或后台成员会撤销相关会话。内容移除、评论删除和用户停用要求填写处理原因。
- 对外的后台能力以现有服务端接口为准；界面不提供“改密码以外的账户恢复”、系统配置写入或批量删除等未实现操作。

## 后续可规划能力

以下需要新增数据模型、接口或独立运维服务，当前界面不伪装成已支持：

1. 用户举报与申诉队列、处理 SLA、审核分派和复核流。
2. 更细的消息/活跃口径、趋势环比、时区配置和全量异步报表导出。
3. 集中日志、历史服务指标、备份/恢复、告警通知和故障事件时间线。
4. 成员多因素认证、管理员登录设备查看、账号恢复与密码重置流程。
5. 可配置的审计保留策略、审计过滤器和不可变归档。

这些项目应先补服务端权限、留痕和数据保留设计，再开放对应后台操作。
